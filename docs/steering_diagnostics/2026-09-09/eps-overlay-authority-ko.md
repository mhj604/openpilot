# 최대 명령이 전달돼도 충분히 꺾이지 않는 원인과 해결 경로

> 게시용 보관본. 작성 시점과 후속 정정을 구분한다. 최신 요약과 읽는 순서는 [기록 안내](README.md)를 참조한다. 원본 주행 데이터·화면·비공개 첨부는 로컬 보관이며 저장소에 포함하지 않는다.

2026-09-09. 실제 C2 주행 기록 기준 `4caf69d`. 차량은 2019 그랜저 IG HEV, 순정 SCC·레이더·전방 카메라 없음, 일반 크루즈와 기존 C-MDPS를 사용하는 구성이다. C2 자체 카메라는 별개다.

## 결론

**현재 가장 유력한 설명은 외부 자동조향 요청 경로의 실효 보조력이 상단에서 포화되고, 그 보조력으로는 해당 순간의 조향 부하를 충분히 이기지 못했다는 것이다.** 이는 모터 전체의 물리적 최대 출력 또는 고장을 확정하는 설명과 다르다.

이번에 새로 얻은 근거는 초기 정차 시험의 **순간 최고 출력이 아니라 최대 명령 유지 중 출력 중앙값**이다. 원시 요청 120→240→320에서는 출력 보고값이 3.9→7.8→10.4로 증가했지만, 384에서도 중앙값이 10.4였다. 명령을 320에서 384로 20% 늘렸는데 이 보고값의 중앙값은 늘지 않았다.

이 숫자로 내부 제한값이 정확히 320이라고 단정하거나, 이를 실제 Nm로 환산하거나, 전 속도·좌우 방향에 공통인 특성이라고 주장하지 않는다. 다만 상단 요청이 추가 보조력으로 이어지지 않는다는 가설은 이전보다 구체적으로 뒷받침된다.

TX 기록의 최대 단계 페이로드는 각각 `(요청 240, 활성 1, fault-request 0)`, `(320, 1, 0)`, `(384, 1, 0)`였다. 단순히 CSV의 command 열만 384이고 기록된 송신 바이트는 320으로 잘렸던 것은 아니다. 옛 CSV의 TX 기록 자체를 독립적인 EPS 내부 수신 확인으로 과장하지 않는다. 최근 C2 기록에는 별도의 송신 확인 프레임과 MDPS 반응이 있다.

### 이전 해석에서 정교해진 부분

순간 최대값만 보면 240에서도 10.1이 나와 ‘240부터 포화’처럼 보일 수 있다. 유지 구간의 중앙값은 7.8이므로 그 표현은 정확하지 않다. 이번 자료는 **적어도 240→320에서는 출력 보고값이 증가했고, 320→384에서는 추가 증가가 보이지 않았다**고 정리하는 것이 맞다.

각 파일은 별도 시험이며 시작 각도, 유지 시간과 부하가 완전히 통제된 한 실험이 아니다. 384에서는 몇 초 동안 10.3~10.5에 머문 점이 유의미하지만, 이것만으로 정확한 공장 보정 곡선을 얻은 것은 아니다.

옛 CSV 열 이름에 `output_torque_nm`이 들어가 있지만, 사용한 DBC의 출력 신호 물리 단위가 확정되지 않았다. 이 보고서는 이를 **출력 보고값**으로만 사용한다. 다른 차의 같은 숫자와 물리 토크를 동일시하지 않는다.

## 2. 최근 실제 우회전과 연결되는가

2026-09-08 C2 원본에서 이미 분리한 사용자 확정 우회전이다. 초반 12초 구간이 아니다.

| 3:32.30 | -384 | +41 | -10.4 | -36.7° | 최대 요청 중 각도 변화가 작음 |

| 3:33.70 | -265 | -240 | -17.0 | -102.7° | 수동 회복 조향 |
| 3:34.00 | 0 | -403 | -24.3 | -146.1° | C2 요청 해제, 수동 조향과 기본 보조 |

이는 ‘출력 신호가 10.4에서 소프트웨어 표시상 잘린 것’이나 ‘이 장치가 어떤 상황에서도 10.4보다 큰 보고값을 낼 수 없음’과 맞지 않는다. 수동 입력이 추가될 때의 출력과 외부 자동조향만 있을 때의 출력을 구분해야 한다.

단, 수동 구간은 힘·속도·각도·타이어 부하가 함께 달라졌다. 모터 전류나 실제 축 토크를 직접 측정한 것도 아니다. 따라서 이 비교를 ‘C2도 24.3까지 요구해도 된다’거나 ‘모터가 정상임이 증명됐다’는 결론으로 바꾸지 않는다.

전체 주행 기록에서 오류·운전자 원시 토크 크기 30 초과·80° 초과 각도·메시지 시각 차이 30 ms 초과를 제외한 보조 집계에서도, 오른쪽 20~30 km/h·명령 384 표본 83개의 출력 크기 중앙값은 10.5였다. 30~40 km/h의 명령 192~255 표본 42개는 중앙값 7.5, 256~319 표본 18개는 9.75였다. 서로 다른 부하의 표본이므로 정밀 응답 곡선으로 쓰지는 않는다.

## 3. 왜 힘을 계속 주는데 각도가 더 증가하지 않는가

현재 `LKAS11`의 핵심 명령은 특정 각도로 이동하라는 위치 명령이 아니라 외부 조향 토크 요청이다. 타이어가 방향을 바꾸며 받는 힘, 복원력과 조향계 마찰에 비해 외부 보조력이 충분하지 않으면, 같은 요청을 유지해도 원하는 만큼 회전하지 않을 수 있다. 더 오래 요청한다고 힘이 시간에 따라 무한히 누적되는 구조가 아니다.

외부 자동조향 요청은 일반적인 운전자 조향 보조와 같은 권한을 뜻하지 않는다. 수동 조향에서는 운전자의 기계적인 힘과 기본 EPS 보조가 함께 작용한다. EPS 연구에서도 이 두 입력과 타이어의 복원력을 구분한다. 해당 논문은 HILS 연구이지 이 그랜저의 제한을 해제하는 소프트웨어가 아니다.

## 4. 외부 자료에서 직접 확인한 관련 사례

### A. 명령을 받아도 더 큰 출력이 나오지 않는 상단 영역

openpilot의 [스팅어 지원 변경 PR #25866](https://github.com/commaai/openpilot/pull/25866)에서 EPS 펌웨어를 분석한 개발자 gregjhogan은, 상한을 높일 때 명령이 송신되는지만 볼 것이 아니라 모터 출력이 증가하는지 봐야 하며, 상단에 효과 없는 영역이 있으면 제어가 나빠질 수도 있다고 설명했다. 운전자 조향 보조와 차선 유지 보조의 허용량 차이도 지적했다.

해당 스팅어 차주는 이후 운전자 개입 없이 출력 보고값이 증가한 기록을 제출했고 변경은 병합됐다. 이것은 **어떤 차는 상한 변경으로 실제 여력을 더 사용할 수 있지만, 모든 현대·기아 차량이 그런 것은 아니다**라는 사례다. 스팅어의 숫자·R-MDPS를 사용자의 C-MDPS에 그대로 적용하지 않는다.

### B. 현대·기아 내부에서도 외부 조향 능력이 다름

[PR #23255](https://github.com/commaai/openpilot/pull/23255)는 외부 조향 능력이 낮은 차량과 높은 차량을 별도 상한으로 다루는 변경이다. 그랜저의 현재 한도가 정확히 어느 값인지 알려 주는 문서는 아니다.

[PR #19628](https://github.com/commaai/openpilot/pull/19628)에 제시된 토크 크기·시간·각도 오류 조건은 **팰리세이드 펌웨어 기준**이라는 단서가 있다. 이를 그랜저의 확정 한도, 또는 409까지 안전하다는 허가로 사용하지 않는다.

### C. 부하 또는 실제 이상은 별도 가능성

현대의 [C-MDPS 정비 자료 20-ST-001H](https://static.nhtsa.gov/odi/tsbs/2020/MC-10170896-0001.pdf)는 전원·열 보호와 고장 코드가 없는 기계적 걸림도 다룬다. 다만 해당 문서의 Azera는 **HG**이며 IG HEV에 적용할 수 있는 직접 수리 지시가 아니다.

이 자료를 근거로 배터리 교환, 임의의 윤활, 조향계 분해나 보정 초기화를 권하지 않는다. 의미는 ‘오류 비트가 0이어도 모든 기계·전원 이상을 배제할 수는 없다’는 정도다.

### D. 비선형 보정은 실제 상한을 늘리는 기술이 아님

[comma의 조향 응답 자료](https://github.com/commaai/comma-steering-control)는 EPS 내부 처리·속도·펌웨어 등에 따라 명령과 반응 관계가 비선형일 수 있음을 설명한다. 이런 관계에 맞춘 보정은 상한 안에서 제어 정확도를 개선할 수 있지만, 출력이 이미 평탄해진 구간에서 추가 물리 보조력을 만들지는 못한다.

| 90° 오류 또는 140° host 차단 | 초기 부족은 약 36° | 초기 부족의 원인 아님. 다른 구간의 별도 현상 |

‘내부 제한’과 ‘정상 외부 보조력이 부족함’은 반드시 서로 다른 원인이 아니다. **정상적인 외부 요청 한도가 낮아서 도로 부하를 못 이기는 한 현상**일 수 있다. 이를 나눠 부르더라도 서로 독립적인 두 고장이 발견된 것은 아니다.

## 6. 해결 경로 — 기대 효과를 구분

### 1) 비선형 요청 보정과 포화 관리: 제어 품질 개선 후보

실제로 효과가 있는 요청 범위를 제어기가 알도록 구성하면 상단의 효과 없는 요청 영역에 머무르거나 그 영역을 내려오는 동안 반응을 잘못 예측하는 일을 줄일 수 있다. 이는 단순히 Kp/Kf를 올리는 것과 다르다.

그러나 이번 초기 정차 자료만으로 전 속도·좌우의 변환식을 만들거나 상한을 320으로 바로 바꾸는 것은 권하지 않는다. **최대 보조력 자체가 그대로라면, 이를 개선해도 같은 급커브의 자동 완주를 보장할 수 없다.** 사용자가 제외한 지연/preview 조정을 새 이름으로 다시 제안하는 것도 아니다.

### 2) 외부 보조력 자체를 늘리려면: 정상 지원 범위에 대한 근거가 필요

현재 EPS가 원래 더 큰 외부 보조력을 지원하는데 잘못된 적용 사양·명령 규격·보정 때문에 못 쓰는 경우라면, 정상 사양으로 맞추는 소프트웨어 대응이 근본 해결 후보가 된다.

하지만 이번 조사에서는 **56340-M9000/M9050 또는 사용자의 정확한 EPS에 적용 가능한 승인 업데이트·코딩·별도 정상 조향 모드**를 확보하지 못했다. 최신 각도 제어용 메시지나 다른 차종 펌웨어를 보내면 된다는 결론은 낼 수 없다. 384→409 증가도 이미 평탄한 응답이 다시 증가한다는 근거가 아니다.

부품 교체는 이번 해결 제안에 넣지 않는다. 고장 코드를 지우거나 보호를 끄는 것도 외부 보조력 확보와 동일하지 않다.

### 3) 비정상적인 조향 저항이 있는 경우: 정상 상태 복구가 해결 후보

타이어·조향계·전원·센서 상태가 정상에서 벗어났다면 그 원인을 정상 범위로 복구하는 것이 필요한 힘을 낮추거나 보조력을 회복할 수 있다. 하지만 현재 자료에는 해당 이상을 확정할 근거가 없으므로 특정 부품·공기압·윤활·보정값을 처방하지 않는다.

저속이면 무조건 해결된다고 하지 않는다. 속도가 낮아도 좁은 경로에 필요한 각도와 마찰 부하가 사라지는 것은 아니며, 사용자가 2~8 km/h에서도 부족했다고 보고했다.

## 7. 실제 결론과 중단선

이번 분석은 ‘모터가 힘이 없다’보다 **‘외부 요청이 더 큰 보조력으로 변환되지 않는 상단 구간이 있다’**는 쪽으로 원인을 좁혔다. 다음 소프트웨어 설계의 대상은 이 입력-출력 특성이지 속도 표시 정리, 계기판 UI, 경고 표시가 아니다.

다만 현재 자료로는 내부 제한이 정상 사양인지, 적용 사양 차이인지, 부하와 결합한 다른 현상인지까지 확정하지 못한다. 정상 외부 보조력의 한계가 실제 필요한 힘보다 작다면, 같은 한도와 같은 도로 경로를 유지한 채 C2 계산만 바꾸어 자동 완주시키는 해법은 만들 수 없다. 이를 해결한 것처럼 작은 튜닝 변경을 제시하지 않는다.

## 조사 범위와 보존

Search 스킬로 3개 조사 갈래(개발 사례, EPS 기계·제어 원리, 제조사 정비 자료)를 검색했고, 후속 표적 검색을 포함해 Exa 요청 결과 수는 총 50건이다. 중복·무관 자료를 포함한 요청 수이며 50개의 독립적 증거라는 뜻은 아니다. 핵심은 제작자의 GitHub 논의, EPS 연구 원문, 제조사 문서와 사용자 원본 기록이다. 검색된 HG 정비 문서, 후기형·CAN-FD 각도 제어 코드, 타 차종의 토크 숫자를 IG HEV 처방으로 가져오지 않았다.

이번에는 이 보고서만 새로 작성했다. 기존 파일·C2 실행 코드·Params·펌웨어·크루즈 버튼·WebUI는 바꾸지 않았다. 차량 접속, 명령 송신, 재부팅, 신규 주행, 테스트·QA는 수행하지 않았다. 원본 CSV와 기존 주행의 저장 표본을 읽어 분석했다.
